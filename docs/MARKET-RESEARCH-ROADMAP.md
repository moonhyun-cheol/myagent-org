# 시장조사(심층리서치) 개선 계획

기준: 커밋 `356126f` + 미커밋 변경(4·5단계 작업분). 대상 시장은 미국이다.

## 결정 사항

| 항목 | 결정 | 비고 |
|---|---|---|
| 리포트 종합 주체 | **현재 프로그램(앱)의 LLM API** | 2026-11-16 사용자 결정. 로컬 Ollama(`qwen2.5:7b`)는 쓰지 않는다 |
| 리뷰 원문 수집 | 새 유료 API 없이 앱이 이미 가진 도구부터 확인 | 위 결정을 이렇게 해석함. 다르면 정정 필요 |
| 파이프라인 역할 | 근거 수집·검증만 (LLM 없음, 템플릿 없음) | 바뀌지 않음 |
| 타당성·기획서 | 닫힌 상태 유지 (`unavailable`) | 내부 자료 인덱스 연결 전까지 |

## 현재 구조

1. 호스트(앱)가 사용자 메시지를 브리프로 넘겨 `pipelines/market_research.py research`를 실행한다.
2. 파이프라인(`agents/evidence_pack.py`)이 영어 검색어 6~10개로 검색하고, 본문을 읽고, 미국·주제 조건을 통과한 발췌만 근거 팩(`evidence_pack.json`, `research_report.md`)으로 쓴다.
3. 호스트는 `research_report.md`를 LLM을 거치지 않고 채팅에 그대로 게시한다.

## 단계

### 1. 배포 준비 — 4·5단계 이후

- `feature-packs/market-research-runtime/feature.json`의 `update_sequence` 1 → 2 (ddgs `==9.16.1` 고정 반영)
- 조직 모듈 업데이트 23 게시, `npm run verify:all`
- 로컬 설치본 반영

### 2. 호스트 연동 정리 — 호스트 저장소

- `normalizeFailureStatus`가 `needs_brief`·`insufficient_evidence`·`unavailable`을 오류로 바꾸지 않게 한다.
- 성공 응답의 머리말("… → 리포트 작성")과 꼬리 문구("타당성 또는 기획서까지")를 현재 동작에 맞춘다.
- 실행 전에 출력 폴더를 만들지 않는다(`defaultSpawn`의 `mkdirSync`).

### 3. 앱 LLM으로 종합 — 호스트 저장소, 효과가 가장 큼

- **경로:** 호스트의 일반 딥리서치 모드(`core/src/chat/modes/deep-research.ts`)는 `ProviderStore`와 `ResolvedModelRoute`로 앱에 설정된 LLM을 부른다. 시장조사 모드(`market-research.ts`)는 이 둘을 받지 않으므로 같은 방식으로 넘겨받게 한다.
- **브리프 구조화:** 같은 LLM이 메시지를 읽고 새 조사인지, 품목·영문명·시즌·경쟁사·가격대를 채워 필드 인자로 넘긴다. 후속 요청이면 파이프라인을 부르지 않는다. 규칙 파서는 필드가 없을 때만 쓴다.
- **종합:** 파이프라인이 `ok`면 `evidence_pack.json`을 LLM에 넘겨 스킬 문서의 「근거 팩으로 리포트를 쓸 때」 규칙으로 리포트를 쓰게 한다. 모든 문장에 근거 번호(E1…)를 달게 하고, 없는 번호·URL은 코드가 걸러낸다.
- **파이프라인 쪽 준비:** 발췌가 근거당 최대 720자라 종합 재료가 부족하다. 근거마다 본문 텍스트(상한 있음)를 함께 저장한다.

### 4. 근거 팩 규칙 결함 — 작업 폴더, **반영·검증됨 (2026-11-16, 미커밋)**

| 문제 | 수정 |
|---|---|
| 주제 판정이 영문명의 모든 단어를 요구(카고바지 무관 판정 12건) | 마지막 명사 필수 + 앞 단어 절반 이상. 한국어 품목명은 판정 용어에서 제외 |
| `$17.9 billion`이 `$17`로, `$1,299`는 미검출 | 금액 단위가 붙은 수치는 가격에서 제외, 천 단위 쉼표 지원, CA$ 등 제외 |
| Walmart·Target 목록 페이지 유입 | 소매처별 상품 URL 표(`/dp/`, `/ip/`, `/p/`)로 일반화, 정확한 호스트만 대상 |
| 결과 0건 검색 미기록 | `empty_queries` 통계 + 수집 요약 표시 |
| `.com` 해외 사이트 통과 | 본문 페이지는 `<html lang>`·`og:locale`, 요약문은 외화로만 적힌 가격으로 판별. 이유별 건수 표시 |

### 5. 품질 측정 기준 — 작업 폴더, **도구 추가됨**

- 도구: `agent-module/market_research/cqr_product_pipeline/tools/bench_evidence.py`
- 고정 브리프 5개: `work_boots`, `cargo_pants`, `ski_pants`, `slacks`, `outdoor_category`
- **기록·재생:** `--record`로 실조사의 검색 결과와 본문을 저장하고, `--replay`로 같은 원자료를 현재 규칙에 다시 통과시킨다. 규칙 변경 효과를 검색 엔진 편차 없이 비교할 수 있다.
- 지표: 빈 검색, 결과, 미국 외 제외(이유별), 목록 제외, 주제 무관 제외, 본문 수집, 근거·본문 근거, 종류별 근거, 가격 있는 경쟁사 근거, 수치 있는 시장 근거, 소셜 근거, 소요 시간
- **사람 판정:** `--sheet`가 근거마다 O/X를 적는 판정표를 만든다. 한 번 판정해 기준선을 만들고, 이후 개선은 칸 수가 아니라 쓸 수 있는 근거 비율로 본다.

- cargo_pants 재생에서는 새 규칙이 기록에 없는 페이지 2개를 읽으려 해 실패로 셌다(`unrecorded 2`).
- 실조사 1회(cargo_pants, 앱 venv, 기록: `rec-new/`): 33초, 빈 검색 0, 결과 33, 목록 7, 주제 무관 5, 본문 9/16, 근거 18 (본문 8), 리뷰/경쟁사/시장 9/5/4. 재생 결과와 같은 경향.
- 언어 판별(`<html lang>`·`og:locale`)은 실조사에서 내려받은 12페이지 모두 `en`/`en-us`로 읽혔고, 걸러진 페이지는 없었다. `rec-base`에는 언어 정보가 없어 재생으로는 확인할 수 없다.
- 테스트: `test_evidence_pack`·`test_dispatcher`·`test_run_research` 59개 통과.

4단계 후에도 남은 것:

- **가격 표기가 제품 가격만 잡지 않는다.** cargo_pants에서 reddit 비유 문장의 `$120`(기타 가격), 시장 기사의 Prada `$890`·`$620`이 잡혔다. 어떤 가격이 경쟁 제품 가격인지는 3단계 LLM이 판단한다.
- **경쟁사 상품 페이지를 읽어도 가격이 없다.** cargo_pants의 5.11 상품 페이지 본문에 가격이 없었다. 스크립트로 가격을 넣는 페이지로 보이나 확인하지 않았다.
- **완화된 주제 판정은 `tactical pants`(cargo 없음) 페이지도 받는다.** 인접 품목이라 받아들이되, 종합 단계에서 구분해야 한다.
- slacks는 시장 근거 0건, ski_pants는 수치 있는 시장 근거 0건 그대로다.
- Walmart 리뷰·상품 페이지는 `URLError`, pewpewtactical·thirstybear는 403으로 본문을 못 읽는다(6단계).

### 6. 리뷰 원문 확보 — 접근 확인 후 결정

- 현재 reddit·Amazon은 본문 0건, Trustpilot·BBB는 403.
- 후보: 미국 소매처·전문 리뷰 사이트(REI, OutdoorGearLab 등) 본문 수집, 앱의 브라우저 도구로 수집.
- 후보 모두 실제 접근 여부를 먼저 확인한다.

### 7. 정리

- 3단계 후 근거 팩이 `deep_research`에 의존하지 않게 하고 레거시 LLM·템플릿 코드를 걷어낸다.
- RAG 테스트 10건은 데이터가 없으면 건너뛰게 바꾼다.
- 임시 폴더 `_local/cache/mr-*` 정리.
