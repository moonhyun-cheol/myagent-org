# Discord 슬래시 명령 — 최종 답변 양식 규약 (SoT)

업무 Discord 봇의 최종 사용자 답변은 보기 좋은 재요약이 아니라 아래 고정 문자열·줄 구조를 따른다. 서비스가 `payload.message`를 제공하면 이를 최우선으로 그대로 전달하며 Core가 제목, `engine`, `action`, `status`, stdout/stderr를 덧붙이지 않는다.

## 0. 공통 규칙

1. 기본 출력은 Discord plain text다. 마크다운은 경로 escape와 코드펜스에만 제한적으로 쓴다.
2. 줄바꿈은 `\n`이며 섹션 사이 빈 줄은 아래 양식에 있는 곳만 둔다.
3. 경로는 백틱을 작은따옴표로 바꾸고 `_`는 `\_`, `*`는 `\*`로 escape한다.
4. 단건 본문은 보통 1900자 이내다. 넘으면 여러 메시지로 나누고 각 끝에 `(i/total)`을 붙인다.
5. 내부 실행 메타, Markdown 표, 임의 이모지, 없는 필드·경로·건수를 추가하지 않는다. 없는 선택 줄은 생략한다.
6. 제목과 라벨은 이 문서의 고정 문구를 완전 일치로 사용한다.
7. ACK와 최종 결과를 섞지 않는다.

## 1. 장시간 명령 ACK

```text
처리 접수 완료
- command: {command_id}
- request_id: `{uuid}`
작업이 길어질 수 있어 백그라운드에서 실행합니다.
결과가 준비되면 이 채널로 안내됩니다.
```

쉼표 배치는 command 다음에 아래 두 줄을 넣는다.

```text
- batch: {N}건 (한 번에 실행, 상한 {cap}건|무제한)
- {N}건 배치 접수 · 완료까지 {시간힌트} 소요될 수 있습니다.
```

대기열:

```text
처리 접수 완료 (대기열)
- command: {command_id}
- 대기 순서: {n}
- request_id: `{uuid}`
작업이 길어질 수 있어 백그라운드에서 실행합니다.
결과가 준비되면 이 채널로 안내됩니다.
```

이미 실행 중:

```text
CTR 작업이 이미 실행 중입니다.
완료 후 다시 요청하세요.
```

동기 queued:

```text
처리 접수 완료
- job_ids: `{id}`, ...
결과가 준비되면 이 채널로 안내됩니다.
```

## 2. 쉼표 배치 래퍼

```text
{명령표시명} ({N}건)

[1/N] {세그먼트원문}
{상태마크} {단건본문}

[2/N] {세그먼트원문}
{상태마크} {단건본문}
```

상태마크는 성공 `✅`, 재고없음/미발견 `—`, 오류 `⚠️`, 스킵 `⏭`만 쓴다. 길면 `{라벨} (N건) (계속)`으로 이어가고 메시지 끝에 `(1/3)`을 붙인다.

배치 미지원:

```text
{라벨}: 이 명령은 쉼표(,) 배치 입력을 지원하지 않습니다. 한 번에 하나씩 요청하세요.
```

## 3. 명령별 최종 결과

### 3.1 `/CTR`

도움말:

```text
사용법: /CTR <LinkPR>
예: /CTR TAC_BOONIE
여러 건: /CTR TAC_BOONIE, CRGO_PT (쉼표 구분)
간략모델 입력 시 dictionary LinkPR로 변환됩니다.
기간 생략 시 ISO 기준 3년 전 동주 월요일 ~ 전주 일요일.
```

dry-run:

```text
CTR 자료 다운로드/병합 드라이런
조건: {root_page}
기간: {start_day} ~ {end_day}
```

성공:

```text
======작업 완료======
CTR 리포트 ({LinkPR})
기간: {YYYY-MM-DD} ~ {YYYY-MM-DD}
데이터: {download_data_rows}행 / RAW {processed_count}개
파일:
{escaped_path_1}
{escaped_path_2}
```

행수·RAW 개수는 존재하는 값만 ` / `로 연결하며 파일에는 리포트 경로만 둔다. 일부 성공은 첫 줄을 `======작업 일부 완료======`로 바꾸고 아래 블록을 붙인다.

```text
###### 확인 필요 ######
{raw_file}: {error}
```

payload.message가 없을 때만 Gate 제목 `CTR 자료 다운로드 및 리포트 작성 완료` 또는 `CTR 자료 처리 실패`를 쓴다.

### 3.2 `/발주검토자료`

성공:

```text
======작업 완료======
{escaped_output_path}
피벗_월별 시트 추가
```

피벗 줄은 ON이고 성공했을 때만 둔다. 일부/실패:

```text
======작업 일부 완료 / 확인 필요======
{경로들 또는 없음}

###### 확인 필요 ######
{raw_file}: {error}
```

산출물이 없으면 `산출물 없음` 또는 오류 문자열을 쓴다. 파일명 stem을 간략모델 필터로 단정하지 않는다.

### 3.3 `/미국샘플재고`

재고 있음:

```text
스탁: {C스탁|M스탁|A스탁}
{필드명}: {값}
{필드명}: {값}

부족: {필드1}, {필드2}

출처: BMS gdslist ({url}{path})
```

값이 있는 필드만 출력한다. 빈 필드는 본문에 넣지 않고 `부족:`에만 둔다. 확인 항목이 없으면 `(확인된 항목 없음)`을 쓴다. 필드 이름과 순서는 고정이다.

- C스탁: `박스바코드`, `Style`, `Size_Name`, `Total Unit`, `모델명_사이즈`, `SKU`, `상품바코드`, `BL`
- M스탁: `모델명`, `색상(라벨번호)`, `사이즈`, `수량`
- A스탁: `SKU`, `수량`, `재고위치`

재고 없음:

```text
재고 없음
조회: {모델/색/사이즈 또는 raw}
lookback {days}일 · 스탁 {C,M,A 또는 고정} · API행 {n}
```

### 3.4 `/반품율분석` · `/반품율검토`

리포트:

```text
반품률 데이터 리포트 작성 완료
- 파일명: {xlsx_basename}
- 경로: {escaped_full_path}
- 분석 데이터: {data_rows}행, SKU {unique_skus}개
- 카이제곱: 유의 {n}건 ({target별})
```

실패 시 제목을 실패로 바꾸고 사유·조치·참고 중 존재하는 줄만 추가한다. 업데이트:

```text
반품률 자료 업데이트 완료|실패
- Drive→NAS: {결과}
- 분석: auto_run 완료 ({days}일 단위, {periods}구간, force)
```

재처리:

```text
반품률 데이터 재처리 완료|실패
- 기간: {start} ~ {end} ({n}일)
- 복구 백업: {path}
- 처리 결과: {n}일
```

업데이트·재처리에는 카이제곱 줄을 넣지 않는다. 제목은 `반품률`, 명령은 `반품율` 표기를 유지한다.

### 3.5 `/발주서등록`

```text
발주서 등록 완료|실패
- 대상: {PO번호} / stage={stage}
- 오류: {msg}
- 생성 파일:
  - {key}: {escaped_path}
- 후속 조치 필요:
  - {action_item}
- 조치 후 이어가기:
  - /발주서등록 {PO} 모델
  - /발주서등록 {PO} 전체
- 후속 조치: 없음
- stderr: ...
```

없는 선택 줄은 생략한다. 승인 완료형 제목은 `====== 작업 완료 ======` 다음 `발주서 등록({proposal_id}: {approval_id})`를 쓸 수 있다.

### 3.6 `/라이브계절지수`

서비스 message 우선:

```text
======작업 완료======
LiveSI 기초자료 작업
실사용 데이터: {escaped_path}
SI 출력: {escaped_path}

{error lines}
```

message가 없을 때 Gate 형식:

```text
LiveSI 기초자료 작업 완료|실패
검증:
- 최근 완성 주: {rows}행 / 주문상품건수 {qty}
- 직전 주: {rows}행 / 주문상품건수 {qty}
실사용 데이터: {path}
SI 출력: {path}
DRAFT 검토: {n}개 파일 오늘 수정 확인
확인 필요:
{errors}
```

### 3.7 `/박스바코드생성`

```text
======작업 완료======
업체: {vendor}
바코드: {barcode}
수량: {n}장
연번: {serial} ({year})
PDF: {path}
이미지: {img_dir} ({image_count}장)
VT3 리스트: {list_path}
```

실패 제목은 `======작업 실패 / 확인 필요======`, dry-run은 `[dry-run] {vendor} · 바코드 {barcode} · {n}장 (연번 {serial})`이다. Discord에는 **payload.message만** 노출하며 engine/stdout 블록을 붙이지 않는다.

### 3.8 `/모델가계도`

~~~text
모델가계도 완료
Query: {query} ({query_type})
파일: {output_path}
{optional output_note}

```
{ascii_tree}
```
~~~

실패는 `모델가계도 실패: {reason}`이다.

### 3.9 `/childasin`

```text
Child ASIN {n}건 저장
PRSKU: {page_sku}
파일: {xlsx_path}
```

0건은 `Child ASIN: 없음`, 도움말 제목은 `PR Child ASIN 목록 조회 (Looka AMZ인벤 / Zinven)`, dry-run 첫 줄은 `dry-run: Zinven 조회 예정`이다.

### 3.10 `/발주정보용판매`

성공 권장 최소형:

```text
발주정보용판매 완료
- 산출물:
  - {path}
- 처리 파일: {n}
```

스킵 문구는 `처리할 판매 raw 파일이 없습니다.`, 실패는 `발주정보용판매 실패: {exc}`다. 엔진/stdout 덤프를 붙이지 않으며 쉼표 배치 불가 문구를 적용한다.

### 3.11 `/ask`

```text
답변:
{본문}
```

### 3.12 `/std-list`

표준 명령 목록과 짧은 설명만 표시한다.

## 4. 검증 체크리스트

1. 명령과 ACK/최종 단계, 단건/배치, 성공/일부/실패/없음/dry-run/help를 구분했는가?
2. 고정 제목 문자열과 줄 구조가 일치하는가?
3. 없는 필드를 만들지 않았는가?
4. 경로 escape를 적용했는가?
5. 미국샘플재고의 스탁별 필드 순서·한글 라벨이 맞는가?
6. 반품율 모드별 제목과 `반품률` 표기가 맞는가?
7. 내부 실행 래퍼를 붙이지 않았는가?
8. 서비스 `payload.message`가 있으면 문자·줄 구조를 그대로 보존했는가?
